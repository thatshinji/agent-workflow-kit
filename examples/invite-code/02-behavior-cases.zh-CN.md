# 第 2 步产物 —「用邀请码加入」行为清单

> 由 Writer 依据已批准的契约（01）写成，格式遵循 `templates/test-cases/TEMPLATE.md`。这是决策者在第 3 步验收门上批准的版本。最终归档版本——在第 8 步解封隐藏场景并加入教训之后的样子——见 [06-archive-state.zh-CN.md](06-archive-state.zh-CN.md)。

## 1. 意图

### 意图
工作区所有者通过任意渠道分享一个简短的邀请码；任何持有有效邀请码的人，一步就能成为该工作区的成员。

### 不变行为
- 成员列表邀请保持原样，照常工作。
- 加入只授予标准成员角色。
- 重新生成邀请码不影响已有成员。

### 非目标
- 不做一人一链接的专属邀请链接；不做审批队列；不做使用数据展示。

## 2. 行为用例

- **INV-001 有效邀请码加入成功** — Given 某工作区有一个有效邀请码，When 一名非成员提交该码，Then 他成为该工作区的成员，并消耗一次使用次数。
- **INV-002 过期邀请码被拒** — Given 一个已过有效期的邀请码，When 一名非成员提交该码，Then 加入以「已过期」为由被拒绝，且不产生任何成员关系。
- **INV-003 次数用尽的邀请码被拒** — Given 一个使用次数已用尽的邀请码，When 一名非成员提交该码，Then 加入以「次数已用尽」为由被拒绝，且不产生任何成员关系。
- **INV-004 不存在的邀请码不泄露任何信息** — Given 一个根本不存在的邀请码，When 任何人提交该码，Then 加入被拒绝，返回的是通用的「邀请码无效」结果，不透露任何工作区信息。
- **INV-005 阻止重复加入** — Given 一名已经是成员的用户，When 他再次提交该码，Then 加入以「已是成员」为由被拒绝，且不额外消耗使用次数。
- **INV-006 猜码被限流** — Given 一名用户在一小时内已经有 10 次加入失败，When 他再提交任何邀请码（哪怕是有效的），Then 本次尝试被限流。
- **INV-007 重新生成使旧码失效** — Given 所有者重新生成了该工作区的邀请码，When 任何人提交之前的旧码，Then 旧码以无效为由被拒绝，而新码可以成功加入。
- **INV-008 输入会被规范化** — Given 一个有效邀请码，When 用户提交时大小写不同或前后带空格，Then 加入成功。

平台差异点：本步未发现（加入行为在所有客户端上一致；分享邀请码发生在应用之外）。

## 计划大纲（摘要）

- 服务端：邀请码存储 + 按契约实现的加入接口；按用户计数的失败尝试计数器。
- 客户端：一个加入表单 + 五个契约错误码的提示映射。没有客户端专属用例。
