# 契约起草清单

> 用途：契约起草（流程第 1 步）的逐项清单。每一项 Writer 恰好标记一种状态：`decided` / `follows standard`（注明出处） / `open question`。带 ★ 的项是**产品决策**——Writer 永不自行决定，它们列为开放问题交给决策者。Reviewer 先查草稿有没有留白：任一项未标记，草稿打回。

## 1. 接口

- 接口清单（方法 + 路径 + 用途）；请求参数与校验规则（必填、类型、范围、长度上限）
- 响应形状与状态码；业务错误码表（复用项目的单一错误包络）
- 列表接口：分页、默认排序、每页条数上限
- ★ 幂等性：重复提交或网络重试会不会重复创建或重复扣款？（创建与支付类接口必须回答。）

## 2. 数据模型

- 表与字段：类型、默认值、可空性；唯一、外键与 CHECK 约束
- 索引按真实查询模式设计（谁查、按哪些字段查）
- 迁移成对 up/down；存量数据的回填与兼容
- 软删除约定；审计字段（created_at / updated_at / 操作者）
- 一年的数据增长估算；清理/归档策略

## 3. 业务规则

- 状态机：状态、合法迁移、每条迁移由谁触发
- 不变量（必须永远成立的规则——写成可测试的句子）
- ★ 计算规则：<如金额用整数最小单位；统计由代码确定性计算，永不由 LLM 计算>
- 并发冲突：同一记录被同时编辑时的策略（乐观锁 / 最后写入胜出 / 显式冲突）
- 事务边界：哪些步骤必须同成功、同失败

## 4. 授权与安全

- ★ 授权矩阵：每个接口——谁能读、谁能写、谁能删（按角色）
- 数据隔离：`<isolation-id>` 只从已认证的会话中取，永不取自客户端输入；说明每个查询如何校验归属
- 授权测试点：列出每一处"改个 ID 就能摸到别人数据"的位置（这些直接喂给行为清单的强制安全用例）
- 敏感数据：密钥/验证码/令牌只存哈希；日志脱敏规则适用
- 滥用限制：验证码发送、登录尝试、邀请码/令牌猜测的频次上限
- ★ 数据保留与真删除：账号注销 / 工作区解散时，数据如何处置

## 5. 外部依赖与异步工作

- 每个第三方依赖（消息、身份提供方、推送、存储……）：本轮真实接入还是用桩——★ 桩的范围是产品决策
- 每个依赖的失败策略：超时、重试次数、重试副作用（如重复消息）、彻底失败时用户看到什么
- 异步与定时工作：触发方、责任人、失败补偿（提醒、过期、周期性生成……）

## 6. 时间与边界

- 存储用 UTC，展示用用户/工作区的时区；"今天 / 本周"的定义
- 边界值：null、超长输入、0、负数、重名
- ★ 删除语义：实体被删除时，其关联数据如何处置（保留 / 转移 / 匿名化）

## 7. 客户端协调

- 字段可空性与默认值（客户端拿到 null 时怎么办）
- 错误码 → 用户文案映射（服务端提供错误码；客户端翻译成大白话）
- 变更影响：线上接口变更时，哪些客户端必须同步更新

## 8. 验收移交

- 每条契约行为都写成可测试的断言，喂给行为清单（流程第 2 步）
- 桩行为须写明确切返回值；清单中的"桩行为"组据此节写成
