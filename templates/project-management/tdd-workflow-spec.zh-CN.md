# 多 Agent TDD 工作流规范

> 版本：v1.0 · 生效日期：<YYYY-MM-DD>
> 范围：本仓库的全部 agent 与决策者。配套文档：`AGENTS.md`（流程）、`REVIEW.md`、`review-protocol.zh-CN.md`。

## 1. 为什么需要它：先写代码后补测试的偏差

当同一个 agent 先写代码、再补测试时，三种失败反复出现：测试照着实现写、漏掉契约边界；顺利路径占满、失败分支到审查时才浮现，多耗轮次；issue 的验收标准从不与具名测试一一对应。本规范通过让测试**更早、独立、且可被机器检查**，消除这三种失败。

## 2. 四步循环

```text
Step 0: 规格映射（验收标准 → 测试矩阵）
  → Step 1: RED（写出失败的测试，证明它们会失败）
  → Step 2: GREEN（最小实现）
  → Step 3: REFACTOR & GATE（清理，并通过合规门禁）
  → Step 4: 独立 REVIEW（见 REVIEW.md）
```

### Step 0 — 测试矩阵

动任何生产代码之前，先从 issue 的验收标准与契约列出测试矩阵。每个功能都包含：

- **正向用例**：成功响应、必填字段、状态变更。
- **强制负向分支**（按你的领域调整；以下是默认集）：
  - 输入校验失败（空、畸形、非法枚举、超长、尾部垃圾数据）；
  - 认证/授权：未认证、已过期、账号被禁用、**跨 `<isolation-id>` 访问必须被拒绝**；
  - 限流与并发冲突（重复提交、重放、竞态安全）；
  - 下游失败行为（依赖超时或返回 5xx 时用户看到什么——永远不能是误导性的成功）。

### Step 1 — RED

- 在实现文件创建或修改**之前**先写测试。
- 运行它们，确认失败*是因为功能缺失*——并把失败输出留作证据。此时能通过、或根本不可能失败的测试，无效。

### Step 2 — GREEN

- 只写让红灯测试变绿的最小代码。
- 不顺手加料：不加未验证的分支、不加猜测性字段、不做顺手重构。

### Step 3 — REFACTOR & GATE

- 全部测试变绿后，清理重复、注释与错误文案；复查日志/脱敏规则。
- 运行一键门禁（`<make pr-check>`，其中包含 §4 的 TDD 合规检查）。100% 通过后才能开 PR。

## 3. 分区规则

- **后端**：优先表驱动测试；测试名写明业务语义（如"60 秒内重复注册返回 429"）。集成测试对真实测试数据库运行（库名以 `_test` 结尾），且每条测试相互隔离——不要把数据层的行为 mock 掉。失败用例同时断言状态码与错误包络（`code` + 非空的、人类可读的 `message`）。
- **客户端/Web**：契约 schema 测试先行（必填字段、枚举边界——证明坏 payload 会在本地被拒绝）。状态/网络测试覆盖：成功、认证过期被驱逐、业务错误浮现、离线/5xx 降级且**不**误踢用户下线。
- **脚本/工具**：每个门禁或工具脚本都自带测试，包括非法输入与失败退出用例。

## 4. 合规门禁（机器检查）

一个零依赖脚本分析分支 diff（`git diff --name-only <base>...HEAD` 加未提交变更），强制执行：

| 规则 | 触发条件 | 要求 | 豁免 |
|---|---|---|---|
| R1 配对（后端） | `<server-source-glob>` 下的生产源码有变更 | 同一变更中包含测试文件变更 | 生成代码（列明生成路径） |
| R2 配对（客户端） | `<client-source-glob>` 下的业务源码有变更 | 同一变更中包含测试文件变更 | 类型声明、入口文件、纯样式/资源 |
| R3 反向断言 | 任一测试文件有变更 | 新增/变更的测试内容包含负向/边界断言（关键词集按栈而定：状态码 `400/401/403/404/409/429`、`Error`、`invalid`、`reject`、`toThrow`，…） | 带明确错误断言的工具脚本测试 |

零影响保证：纯文档或纯配置分支自动通过；门禁从不追溯评判它生效之前存在的代码。

## 5. PR 证据卡

功能/修复 PR 在正文中包含这份记录：

```markdown
### TDD record
- **Step 1 (RED)**: added `<test file>:<test name>` — verified failing before implementation
- **Step 2 (GREEN)**: implemented `<source file>` — positive and negative tests all green
- **Step 3 (GATE)**: `<make tdd-check>` passed (pairing 100%, negative assertions present)
```
