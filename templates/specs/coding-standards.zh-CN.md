# 编码规范

> **声明**：本文件是*活基线*。它通过普通 PR 修订，**不受**本目录其他文档所适用的冻结规格规则约束。

## 0. 通用约定（所有技术栈）

1. **业务命名**：名字使用领域词汇，与设计稿、API 契约、行为用例中的名字保持一致。不用拼音/缩写拼凑，不做无意义的缩短。
2. **注释解释为什么**，不解释做什么。`TODO` 注释必须带 issue 编号。
3. **用户可见文案集中管理**，放在常量/资源文件里，绝不散落在代码各处。
4. **密钥与个人信息绝不外泄**：手机号、验证码、密钥、令牌和个人数据绝不出现在日志、错误信息或测试快照里。手机号即便要记日志也必须脱敏。

## 1. 机器强制矩阵

项目里的每个技术栈填一行。关键规则为 `error` 级别——`warn` 会让 CI 照样变绿，因此等于不存在。

| 技术栈 | 工具 | 配置文件 | CI 归属 |
|---|---|---|---|
| <后端语言> | <格式化工具 + linter 集合> | `<路径>` | <CI job> |
| <客户端 A> | <linter + 格式化工具> | `<路径>` | <CI job / "平台启动时"> |
| <Web> | <ESLint 同类工具 + 格式化工具> | `<路径>` | <CI job> |
| <样式> | <样式 linter，基础集> | `<路径>` | <如实标注：已接入 / 尚未接入> |

**强制决策**（推荐默认值——你方采用时记下日期）：

1. **增量强制**：linter 只拦截新文件和改动行；存量问题豁免，随文件被改动时顺手清理。<已采用 / 未采用，日期>
2. **从基础规则集起步**：<按技术栈，如 errcheck/staticcheck/ineffassign/unused 的同类物>；风格类重的规则包在基础集跑干净之前不开。<日期>
3. **新平台先用默认规则集**，等第一批代码落地后，再针对真实误报逐条调。<日期>

工具版本处处钉死。CI 里绝不出现 `@latest`：CI 结果只能取决于仓库内容。

## 2. 按语言的约定

项目里的每种语言一小节，每节 5–8 条一行规则，锚定该生态的权威指南（<如语言官方风格指南、框架厂商的 API 设计指南>）。规则要写成 Reviewer 能机械核查或一眼看出的样子。示例形状（替换成你的技术栈）：

### 2.1 <后端语言>

- <错误处理：只处理一次、包装上下文、控制流用类型化错误……>
- <并发：每个后台任务都有退出条件；不留孤儿 worker……>
- <事务：begin/延迟回滚/commit 的模板……>
- <日志：只用结构化日志器，请求级字段含 request id 与隔离 id；不留调试打印……>

### 2.2 <客户端语言>

- <外部数据不强制解包 / 不做不安全转换……>
- <状态管理：状态就近存放；共享状态只走项目选定的机制；未经批准不引入状态库……>
- <异步 UI：任务绑定生命周期；UI 更新在主线程……>

### 2.3 <Web 技术栈>

- <严格类型；`any` 同类物在 error 级别禁用……>
- <框架特有的 effects/状态反模式，及钦定的替代写法……>
- <只用设计令牌：颜色/间距来自令牌文件；机器生成的设计导出文件绝不手改……>
- <语义与目标：交互元素是真正的控件；触摸目标 ≥ 平台最小值……>

## 3. 与评审的联动

严重违反本文件的行为，在 `REVIEW.zh-CN.md` §2 下构成 `failure`。同一类违规第二次出现时，它要变成 lint 规则或门禁脚本检查（见流程的归档步），而不是又一条重复的评审意见。
